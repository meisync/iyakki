What the numbers mean

Impl
How much of the feature's behaviour is written, 0 to 100.
Test 0
Nothing is tested yet.
Test 30
Only parts are tested, with fakes or unit tests; or it has not been tried for real.
Test 50
The behaviour is tested end to end, still on fakes.
Test 70
Proven by an integration test, a virtual-machine boot, the browser harness or a script.
Test 100
Also seen working on the real hardware or screen it is for, or a manual test is recorded as passed. Features that need no hardware reach 100 by tests alone.
Manual none
No manual test is needed.
Manual needed
A person, or the test Mac mini or stick, must try it.
Manual passed
Tried by hand with the date and the machine recorded.
Manual failed
Tried and failed; a known issue (KI-number) says what.

Known issues in short

The honest list is KNOWN-ISSUES.md; it names 131 numbered issues (KI-numbers), grouped by hardware, browser and media, assistant, security, install and tests. Its first section, "Do not use it for", says:

  • KI-001 Production, or any machine that holds data you cannot lose.
  • KI-002 Production clusters.
  • KI-003 Secure Boot on real hardware.
  • KI-004 Fixed in code, hardware check pending.

From the alpha.2 release notes, known limits include: the wake phrase has no real-voice measurement and should stay off; the encrypted home folder is a first version (whole-disk encryption and TPM sealing are not built); Secure Boot is verified in QEMU only on most machines.

Roadmap

Taken only from documents that are public in the repository. Plans can change.

alpha.3 (in progress)

  • Browser sound as a low-latency live source of the mixer, to fix the lag and the tail after stopping (KI-085; tested with a fake sink, not on hardware).
  • Driver and firmware downloads fail within seconds with a plain message when there is no network (KI-083; tested, not yet on hardware).
  • A covered camera is reported as such instead of a bare black picture (KI-082), and the Bluetooth headline stops saying a firmware file is missing when the controller works (KI-084).
  • Client devices (experimental, off unless switched on): a browser page and the iyakki-connect window program, with sound, clipboard, camera frames and the client's own camera and microphone as sources. Tried on Linux with headless Chrome and fakes only (KI-088, KI-089).
  • Bundles with requires ranges and wizards in tile packages (data and checks only), and a developer-mode standing restart grant.

alpha.4 (plan only, nothing built)

  • Support for multiple languages: a framework so that a person or community can build a language as an installable pack (screen text, formats, fonts, keyboard and voice), with tools to make and test it. Not machine translation; English complete, a pseudo-locale and one small sample pack. See the plan.
