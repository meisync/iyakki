# Licensing policy

IYAKKI is Apache-2.0 and free for any use. To keep it that way:

1. **Dependencies must be permissive.** `deny.toml` allow-lists Apache-2.0, MIT, BSD, ISC, Zlib, Unicode, CC0, 0BSD, Unlicense. Run `cargo deny check licenses sources` before adding or updating a crate. GPL/LGPL/AGPL/MPL crates are rejected.
2. **No copied code.** Write original code or depend on a crate; do not paste code from other projects without a compatible license and attribution.
3. **Dependencies in use (verified with `cargo deny`):**
   `wasmtime` Apache-2.0 WITH LLVM-exception · `egui`/`eframe` MIT or Apache-2.0 (bundled fonts: OFL-1.1 / Ubuntu Font Licence, scoped exception in `deny.toml`) · `cpal` Apache-2.0 · `v4l` MIT · `libp2p` MIT · `chacha20poly1305`/`argon2`/`zeroize` (RustCrypto) Apache-2.0 or MIT · `ureq`/`rustls`/`rcgen` Apache-2.0/MIT/ISC (the browser front end's TLS) · `rustybuzz` MIT (text shaping) · `unicode-bidi` MIT/Apache-2.0 · bundled Noto Sans fonts for Indic, Arabic and Hebrew text under the SIL Open Font License 1.1 (text in `crates/iyakki-shell/assets/NOTO-OFL-LICENSE.txt`; DejaVu keeps its own licence) · `webpki-roots` CDLA-Permissive-2.0 (Mozilla CA list) · the WebP decoder (`iyakki-web/src/webp.rs`) is our own code; its constant tables (probabilities, quantiser steps) are the numbers fixed by the VP8 specification (RFC 6386) and were read out of libwebp (BSD-3-Clause) to avoid typing errors — no libwebp code is copied.

   **Written in-house instead of depending on a crate:** the editor engine, syntax highlighter and diff (`iyakki-edit`, no dependencies), the browser (HTML, CSS, layout, images, forms, cookies; `iyakki-web`), the regular-expression engine and the text commands (`grep`, `sed`, `tr`, `cut`, …), Markdown drawing in the chat, the time-zone reader, tar and zip unpacking, the calendar, the local-network scanner, OS entropy (`getrandom(2)` wrapper), shutdown-signal handling (`sigaction`), disk detection and the data-volume logic (`iyakki-storage`). tree-sitter was removed for this reason.

## The licence and proprietary-software gate (release gate point 7)

`./run.sh licence-check` (the program is `iyakki-relcheck licence-check`; `--strict` also fails on REVIEW rows, `--write` refreshes the generated documents, `--no-images` skips the image scan) is one run that exits 1 on any FAIL. It writes nothing outside `legal/` and only with `--write`; it never unpacks an image or touches a drive. Its parts:

1. **Rust dependencies.** Every package of both `Cargo.lock` files that `cargo tree` reaches must be under Apache-2.0 (with or without the LLVM exception), MIT, MIT-0, BSD-2/3, ISC, Zlib, Unicode-3.0 / Unicode-DFS-2016, CC0, 0BSD, Unlicense or BSL-1.0 (an `OR` expression passes when one alternative does, an `AND` when all do; `MIT/Apache-2.0` reads as OR). Anything else (MPL-2.0, LGPL, fonts, data licences, unknown, no licence, a source other than crates.io) fails unless `legal/cargo-exceptions.txt` has a row for that crate **and that exact licence text**, with a reason and a date; an update that changes the licence stops the row applying. GPL, AGPL, SSPL and proprietary licences are not to be put there without the owner's written decision. A failing crate that is only in a lock file (an optional feature that is off) is listed for review, not failed. `cargo deny` stays as the second check (`deny.toml`).
2. **Image content scan.** Every regular file and link of each `target/buildroot-*/images/rootfs.cpio` and `install-root/` is mapped to the Buildroot package that installed it (`build/packages-file-list.txt` of the image's own build, then the Mac and web builds the layered images are repacked from), and the package to its licence (`legal-info/manifest.csv`, falling back to the licence in the package recipe). Links belong to the package that owns their target. It fails on: a file matching a `deny` row of `legal/image-rules.txt` (Apple, NVIDIA, Broadcom-for-Apple firmware, vendor CLIs, FFmpeg and other codec libraries, x264/x265/OpenH264/FAAD/fdk, restricted fonts; the inactive `gst-libav` bridge under `usr/lib/iyakki-av` is the one reviewed `except`), a package whose licence is proprietary, unrecognised or missing from the manifest, a file no package owns and no `own` / `generated` row explains, a font, picture, sound, video or model file that is not owned by a licensed package and not in `legal/assets.txt`, and a missing `usr/share/doc/iyakki/{LICENSE,NOTICE,THIRD_PARTY_LICENSES.txt,LICENSING.md}`. `iyakki-relcheck image-scan --cpio FILE|-` (a pipe from `zstd -dc` works) and `--tree DIR` scan other inputs.
3. **Downloads inventory.** `legal/downloads.txt` has one row per Quick install item and per command-line tool: licence, delivery (`download-only` or `nothing-installed`; `shipped` fails), pin kind and pin, what was checked, date. `cargo test -p iyakki-agent --test licence_gate` ties it to the code: a new Quick install item or CLI without a row fails, a digest or version that is not in the source fails, a tool without a checksum in `clis.rs` must be listed as `floating`, and every item must show a licence string. A copyleft or vendor-licensed item whose screen does not say it is downloaded or pulled and never shipped, and every built-in store entry without a licence string, must be listed (dated) in `legal/catalogue-gaps.txt`; a new one fails. **Signed downloads manifest (2026-10-28).** The versions and checksums of these items are also kept in `legal/downloads-manifest.json` (the ISO's offline copy and allow-list; a newer one signed by the owner may change only the version, address and checksum of listed items on their own hosts, never an item, a licence, a flag or a host; [docs/development/DOWNLOADS-MANIFEST.md](docs/development/DOWNLOADS-MANIFEST.md)). `cargo test -p iyakki-agent --lib dlmanifest` ties it to `legal/downloads.txt`: every REVIEW row is covered, licences and pin kinds agree.
4. **Assets.** Every font, picture, icon, sound, video and model file in the repository needs a row in `legal/assets.txt` (licence, origin, `verified` or `unverified`, date, and where it appears inside an image). `unverified` rows are listed as REVIEW.
5. **Notices and SBOM.** `legal/THIRD-PARTY-NOTICES.md` (index of what is used, under what, and what is only downloaded) and `legal/sbom.cdx.json` (CycloneDX 1.5) are generated from the same data, in this repository's own code, with no timestamps; the gate fails when the committed copies differ from a fresh run, so they cannot go stale. `SBOM.json` (SPDX-lite, `iyakki-relcheck sbom`) and `THIRD_PARTY_LICENSES.txt` (`cargo about`) stay as they are. `--write` also writes `legal/sbom-images.cdx.json` with the Buildroot packages found in the scanned images.
6. **`legal-info/` completeness.** For each Buildroot build with a `legal-info/`, every package in `manifest.csv` must have its licence texts and every GPL/LGPL/MPL package its source archive (`legal-info/sources/`): that is the material for the source offer in `docs/LICENSES.md`. A package that owns files in an image but has no manifest row is an image-scan finding.

**Lemonade and model weights (owner decision 2026-10-27).** IYAKKI provides integration code only. Model weights and engine downloads performed by Lemonade or by the person are outside the gate; IYAKKI never redistributes them, ships none, hashes none, and its screens claim no licence for them (the Lemonade server image itself, which the cluster pulls at the click, is a row in `legal/downloads.txt`: Apache-2.0, pinned by digest). The Voice items (Kokoro, Voice: Whisper tiny + Kokoro) therefore have `nothing-installed` rows. **Firmware and downloaders.** Our code contains only the downloader and the licence-display logic for vendor firmware (Hardware firmware item, the Apple firmware extractor, driver packs): no vendor blob is in the repository or in a base image, and the person's click fetches it from the vendor or reads it from the person's own Mac.

**What the gate does not cover.** It reads names, paths, licence fields and the checked-in review files; it does not read file contents. It cannot tell that a file named like a free one is a proprietary one, that a licence field is wrong, or that a package's files differ from its upstream. It does not open the ISO, the install image or the FAT boot image (it scans the `rootfs.cpio` and `install-root` that are packed into them, which are the same inputs, not proven identical to the packed copy). It does not scan the compressed `rootfs.cpio.zst`. It does not check the licence of a dependency of a downloaded program, of what a downloaded program or container later pulls, of model weights the person pulls by name, or of web content the browser loads. It does not check patents (codecs), trademarks or export rules; those are the owner's legal-opinion decisions. Dev-dependencies and build tools on the build machine (the host grub, `grub-mkfont`, the DejaVu fonts it copies) are not covered. The licence text of Rust crates is whatever the crate's `Cargo.toml` states; a wrong or missing `license` field is not detected. `legal/downloads.txt` licences were taken from the product text in the code and the vendor pages named there; they were not each re-read against the upstream LICENSE file.
