# Licensing policy

IYAKKI is Apache-2.0 and free for any use. To keep it that way:

1. **Dependencies must be permissive.** `deny.toml` allow-lists Apache-2.0, MIT, BSD, ISC, Zlib, Unicode, CC0, 0BSD, Unlicense. Run `cargo deny check licenses sources` before adding or updating a crate. GPL/LGPL/AGPL/MPL crates are rejected.
2. **No copied code.** Write original code or depend on a crate; do not paste code from other projects without a compatible license and attribution.
3. **Dependencies in use (verified with `cargo deny`):**
   `wasmtime` Apache-2.0 WITH LLVM-exception · `egui`/`eframe` MIT or Apache-2.0 (bundled fonts: OFL-1.1 / Ubuntu Font Licence, scoped exception in `deny.toml`) · `cpal` Apache-2.0 · `v4l` MIT · `libp2p` MIT · `chacha20poly1305`/`argon2`/`zeroize` (RustCrypto) Apache-2.0 or MIT · `ureq`/`rustls`/`rcgen` Apache-2.0/MIT/ISC (the browser front end's TLS) · `rustybuzz` MIT (text shaping) · `unicode-bidi` MIT/Apache-2.0 · bundled Noto Sans fonts for Indic, Arabic and Hebrew text under the SIL Open Font License 1.1 (text in `crates/iyakki-shell/assets/NOTO-OFL-LICENSE.txt`; DejaVu keeps its own licence) · `webpki-roots` CDLA-Permissive-2.0 (Mozilla CA list) · the WebP decoder (`iyakki-web/src/webp.rs`) is our own code; its constant tables (probabilities, quantiser steps) are the numbers fixed by the VP8 specification (RFC 6386) and were read out of libwebp (BSD-3-Clause) to avoid typing errors — no libwebp code is copied.
   `miniz_oxide` MIT or Zlib or Apache-2.0 (deflate, used to unpack tar.gz and zip downloads) · `nanomp3` MIT or Apache-2.0 (a pure Rust port of minimp3, CC0; decodes MP3 radio and music) · `sha2`, `ed25519-dalek` (RustCrypto) · `serde`/`serde_json` MIT or Apache-2.0. QuickJS-ng (MIT) is vendored and compiled to WebAssembly (see `NOTICE`).
   **Written in-house instead of depending on a crate:** the editor engine, syntax highlighter and diff (`iyakki-edit`, no dependencies), the browser (HTML, CSS, layout, images, forms, cookies; `iyakki-web`), the regular-expression engine and the text commands (`grep`, `sed`, `tr`, `cut`, …), Markdown drawing in the chat, the time-zone reader, tar and zip unpacking, the calendar, the local-network scanner, OS entropy (`getrandom(2)` wrapper), shutdown-signal handling (`sigaction`), disk detection and the data-volume logic (`iyakki-storage`). tree-sitter was removed for this reason.
   **Avoided on purpose:** Slint (GPL-3.0 or commercial), GStreamer bindings (would link LGPL system libs). The optional full web engine uses GStreamer only inside its own separate programs (item 9).
4. **Bootable images.** What ships in the `libre` ISO (from Buildroot's `legal-info/manifest.csv`): Linux kernel (GPL-2.0), BusyBox (GPL-2.0), iproute2 (GPL-2.0+), kmod and libnl (LGPL-2.1+, shared libraries), GRUB (GPL-3.0+, boot loader only), gcc runtime (GPL-3.0 with GCC runtime exception), ca-certificates (GPL-2.0+ script, MPL-2.0 data), iw and wireless-regdb (ISC), wpa_supplicant (BSD-3-Clause), alsa-utils (GPL-2.0, `aplay`/`arecord`/`amixer`, run as separate programs for voice) with alsa-lib (LGPL-2.1+), e2fsprogs (GPL-2.0 `mke2fs`, run as a separate program to create the data volume; its libraries are LGPL-2.1), OpenSSL (Apache-2.0), zlib (Zlib), musl (MIT), plus the statically linked `iyakki` binary (Apache-2.0 and the permissive Rust crates in `THIRD_PARTY_LICENSES.txt`). The optional Mac image adds the out-of-tree kernel module apple-bce (t2linux, GPL-2.0, T2 Macs: sound and internal USB; built by `dist/buildroot/package/apple-bce` against the image's kernel, with two IYAKKI patches under the same licence) IYAKKI's own i915 display-clock patch for the Mac mini 2018 (`0001-drm-i915-skl-keep-the-firmware-cdclk-while-pipes-are-on.patch`; it changes kernel code, so it is GPL-2.0 like the file it changes, not Apache-2.0) and three GPL-2.0 kernel patches for T2 MacBooks (Touch Bar keys, trackpad, Radeon Pro 5300M; from upstream Linux v6.18 and t2linux, source and commit in each patch header, `dist/buildroot/board/iyakki/patches/linux/`); it is kernel code, so like the kernel its source goes into `legal-info/`, and it is not linked with any IYAKKI program. **Secure Boot (optional, when the owner builds with a signing key; `docs/SECURE-BOOT.md`):** the boot partition then also carries `shim` 16.1 (BSD-2-Clause, Red Hat and Intel) and MokManager, taken at build time from Debian 13's packages `shim-signed` and `shim-helpers-amd64-signed` (SHA-256 pinned in `dist/buildroot/secureboot.sh`; shim's binary is signed by Microsoft, MokManager by Debian; IYAKKI does not build or modify them, their copyright files and the package URLs and hashes are written next to them as `SHIM-PROVENANCE.txt`; shim source: <https://github.com/rhboot/shim> and Debian's source package `shim`). GRUB (GPL-3.0+) is rebuilt as one EFI file with an SBAT section, kernel and modules are signed with the owner's key; the kernel carries one small GPL-2.0 lockdown patch (`board/iyakki/patches-sb/`). Build-host tools, never shipped: `sbsigntool` (GPL-3.0), the kernel's `sign-file` (GPL-2.0), openssl (Apache-2.0). Whoever distributes a signed image provides the corresponding source of GRUB and the kernel as for any image, and the source of shim is the Debian source package named above. Nothing of this is in the repository or in unsigned images. The GPL programs are separate executables, so our code stays Apache-2.0, but anyone distributing an ISO must provide corresponding source for the GPL/LGPL parts: `build.sh` runs `make legal-info`, which produces the manifest and source tarballs in `legal-info/`. The image carries `/usr/share/doc/iyakki/` with LICENSE, NOTICE and the third-party texts. Regenerate the latter after changing dependencies: `cargo about generate about.hbs -c about.toml -m crates/iyakki-core/Cargo.toml -o THIRD_PARTY_LICENSES.txt`.
5. **Tools and images fetched at runtime.** The CLI tile downloads vendor programs (kubectl, k3s, Helm, Terraform, GitHub CLI, AWS CLI, Google Cloud CLI, Azure CLI via pip, Arduino CLI, esptool, espflash) into the data folder when an administrator asks, and the container cluster pulls container images (python, node, alpine). None of them is shipped in an IYAKKI image or linked into IYAKKI; each keeps its own licence. Claude Code (Anthropic) and GitHub Copilot CLI (GitHub) are proprietary programs that the person downloads from the vendor at their request (IYAKKI only fetches the vendor's published file and checks its checksum); Node.js is MIT, Python 3 is under the PSF licence (python-build-standalone) and uv is MIT or Apache-2.0, and IYAKKI does not ship any of them either (several are Apache-2.0 or MIT, Terraform's current licence is the Business Source License, and the container images contain GPL/LGPL software). Check a tool's licence before using it in a commercial setting.
6. **Station list.** The radio's starting stations come from the public Radio Browser directory; they are links to public streams, not copies of anything.
7. **Firmware blobs.** `build.sh hw` includes `linux-firmware` files. They are redistributable but **not open source** (each has its own licence, listed in `legal-info/`). The default `libre` image contains none; publish the `hw` image only after reading those licences, and keep the two clearly labelled. Hardware that needs a blob will not work in the `libre` image. The Mac images (`mac`, `macweb`) ship a subset of that set: the files named in `dist/buildroot/board/iyakki/mac-firmware.keep` (Intel and AMD graphics, Broadcom PCIe Wi-Fi and Ethernet, Realtek Ethernet, the MediaTek, Atheros and Ralink USB Wi-Fi adapters, a Realtek USB Bluetooth dongle); no new blob is added, and the `legal-info/` manifest still lists the linux-firmware package whole.
8. **Logo and name.** The logo (`crates/iyakki-shell/assets/logo.png`) must have its origin recorded: whoever supplied it should confirm they own it or that the terms of the tool that made it allow use under the project's licence, before the project is published.  "IYAKKI" was also used by a 1970s US weather-service system and some industrial software; do a trademark search before commercial branding.
9. **Optional full web engine variant (`build.sh web`, `./run.sh build-web`).** The default images contain none of this. The `web` variant adds, as *separate programs and shared libraries that IYAKKI only starts, never links*: WPE WebKit (LGPL-2.1+ and BSD-2-Clause), libwpe and WPEBackend-fdo (BSD-2-Clause), Cog (MIT), the cage kiosk compositor (MIT), wlroots (MIT), Wayland (MIT), libinput and libxkbcommon (MIT), seatd (MIT), Mesa (MIT; llvmpipe/virgl/radeonsi/crocus drivers) with LLVM (Apache-2.0 with LLVM exceptions), eudev (GPL-2.0+ programs, LGPL-2.1+ libraries; `udevd`/`udevadm` run as separate programs), GStreamer and its plugins (LGPL-2.1+) with libvpx (BSD-3-Clause), dav1d (BSD-2-Clause), Opus (BSD-3-Clause) and libvorbis (BSD-3-Clause), ICU (Unicode licence), HarfBuzz, FreeType, fontconfig, cairo/pixman (MIT/LGPL), libsoup (LGPL-2.1+), GLib (LGPL-2.1+), SQLite (public domain), Liberation fonts (SIL OFL 1.1) and DejaVu fonts (Bitstream Vera/DejaVu licence). Corresponding source and licence texts for every component come from Buildroot (`make legal-info`, run by `build.sh`, into `target/buildroot-web/legal-info/`). The LGPL libraries are used as ordinary shared libraries, so a person can replace them. H.264, AAC and MP3 decoding (FFmpeg through gst-libav, LGPL-2.1+ or GPL when built with GPL parts) are left out of the image unless it is built with `WEB_H264=1`; those codecs are patent-encumbered in some countries, which is a separate matter from the copyright licences (`docs/FULL-BROWSER.md`, "Codec policy"). Publish a `web` image only together with its `legal-info/`.
10. **ffmpeg, downloaded by the person (Quick install, Media).** IYAKKI's own media player uses `ffmpeg` only as a separate decoder program started with fixed arguments (`BOUNDARY.md`); nothing of it is linked into IYAKKI and **IYAKKI does not ship it**. The person downloads the static build from its builder, johnvansickle.com (`ffmpeg-release-amd64-static.tar.xz` or the `arm64` one, about 42 MB and 19 MB), into the data folder; the download is checked against the MD5 file the builder publishes next to it (he publishes no SHA-2 sum) and unpacked by IYAKKI's own `.xz` reader (`crates/iyakki-agent/src/xz.rs`). That build is licensed GPL version 3 (it includes GPL parts such as libx264), so the person who downloads it receives it under the GPLv3 from the vendor, with the source the vendor links on that page. H.264, HEVC and AAC are patent-encumbered formats in some countries, which is a separate matter from the copyright licence; as with the web variant's `WEB_H264` policy (`docs/FULL-BROWSER.md`, "Codec policy"), decoding them is the person's choice. The optional image build (`WITH_FFMPEG=1`, `dist/buildroot/configs/iyakki_media.fragment`) instead builds Buildroot's ffmpeg as an **LGPL** build (no GPL or nonfree options, no ffplay); whoever builds and distributes such an image publishes it with its `legal-info/` and decides the codec question for it.
11. **registry:2 (CNCF Distribution), pulled by the cluster at the person's click.** The local image registry (Quick install → Cluster, or Create registry in the private store deploy) makes the cluster pull `docker.io/library/registry:2` (Apache-2.0) from Docker Hub. IYAKKI does not ship, bundle or redistribute that image; only the manifest that names it is IYAKKI's.
12. **Apple Silicon (planned `apple` variant, nothing shipped yet).** Would add the linux-asahi kernel (GPL-2.0), m1n1 (MIT) and Asahi's U-Boot (GPL-2.0+, a separate program in the boot payload) to an optional image; the Asahi installer (MIT) is not shipped, only its package format is produced (`dist/asahi/`, our code, Apache-2.0). Apple's firmware (Wi-Fi, Bluetooth, camera) is not redistributable: the installer extracts it on the user's own Mac, and the package generator refuses to include it. Whoever publishes such an image publishes it with its `legal-info/` (kernel, U-Boot and m1n1 source). See `docs/APPLE-SILICON.md` section 5.
