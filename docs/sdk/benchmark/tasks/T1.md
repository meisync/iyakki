# Task T1: a counter, a notes pane with persistence, and a switch with a chat tool

You are building an IYAKKI app with the UI SDK. Use the skill `iyakki-app-development` and the guide in `docs/sdk/`. Make the app with
`iyakki new-app bench-t1 --dir <a folder outside the repository> --sdk <repository>/crates/iyakki-ui-sdk` (the crate is `iyakki-app-bench-t1`, the
type `BenchT1App`, the id `bench-t1`). Finish when `./run.sh app-check <your app folder>` prints no problems and the visible test passes.

## What the app does

1. Three tabs (buttons named exactly) **Counter**, **Notes**, **Assistant**. Counter is shown first.
2. **Counter**: a button named **More** adds one; the text `Pressed N times` shows the count. The count is kept through the storage port under the key `count`.
3. **Notes**: a text field named **Note**, a button **Add** and a list of the notes (each a row named by its text). Add appends the trimmed text and clears the field; an empty note is refused with a sentence on screen and is not added; at most 100 notes (a further one is refused with a sentence). The notes are kept under the key `notes` (one note per line).
4. **Compact rows**: a button named **Compact rows** on the Notes pane toggles a switch; when it is on the rows use the smallest allowed height (still at least the touch size). The value is kept under the key `compact` as `true` or `false`.
5. **Assistant**: the embedded assistant (ChatView) with two tools of your app: `compact_status` (a read: says whether compact rows are on) and `compact_set` with a boolean argument `on` (a change: the person must allow it on a card before it takes effect). The screen switch and the tool must use the same code and the same stored value.
6. A refusal of the storage port is shown to the person in words; the app does not crash.
