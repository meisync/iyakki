# Task T3: a themed dashboard, list and detail, accessible at three sizes

Make the app with `iyakki new-app bench-t3 --dir <folder outside the repository> --sdk <repository>/crates/iyakki-ui-sdk` (crate `iyakki-app-bench-t3`, type `BenchT3App`, id `bench-t3`). Use the skill `iyakki-app-development`. Finish when `./run.sh app-check <app folder>` prints no problems and the visible test passes. The app has no ports and no chat (a read-only dashboard).

## What the app does

1. Three services, in this order, each a list row named by its name: **Alpha** (status `ok`, note `All systems normal.`), **Bravo** (status `slow`, note `Latency above 300 ms.`), **Charlie** (status `down`, note `Not responding.`).
2. Each row also shows a status dot coloured from the theme (ok, warning, error colours of the Look: no colour written in the source). The status is always also written in words in the detail: the text `Status: ok`, `Status: slow` or `Status: down` (colour alone never says it).
3. The detail shows the service's name as a title, `Status: ...` and its note, on a card drawn with the skin's own radius, shadow and edge.
4. **Wide** panes (size class Medium or Expanded): the list and the detail side by side; the first service is selected at the start; tapping a row selects it; Up and Down move the selection; no Back button.
5. **Compact** pane (a phone): the list alone; tapping a row (or Enter) opens the detail screen in place of the list, with a button named **Back** at the top; Back and Esc return to the list; Esc on the list leaves the app.
6. Everything is named, at least the minimum touch size, and inside the pane at 360x740, 800x480 and 1280x720, at text 1x, 2x and 3x, and in every shipped skin.

## Rules

The golden rules of the skill apply (no styling numbers: radii, gaps, text sizes and line widths all from the skin's tokens). The visible test is `acceptance/T3.rs` (copy to `tests/accept_t3.rs`); a hidden test is also run. Rewrite or delete the scaffold's `tests/starter.rs`.
