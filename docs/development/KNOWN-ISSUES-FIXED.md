# Known issues: the fixed registry

KNOWN-ISSUES.md lists only what is still open (class BUG, UNPROVEN or LIMIT). When an issue is fixed, its entry is **deleted** from that list and its id is recorded here with the evidence, so that a `KI-nnn` cited from FEATURES.md or another document still resolves. `iyakki-relcheck known-issues` reads this file (the ids at the start of each bullet), refuses an id that is both here and in the list, and refuses a citation of an id that is in neither.

Format, one bullet per id, newest last:

`* KI-nnn | YYYY-MM-DD | what was wrong in a few words | evidence: the test, the measurement or the real-device check that proves it`

"Fixed in code, hardware check pending" is not fixed: such an entry stays in the list as UNPROVEN until the check is done.
