# Impl rule of 2026-11-12

Owner decision (2026-11-12): "fully written" means the code is implemented; "fully proven" means fully tested. So the Impl column is about written code only. Work that is written but unverified (fakes only, no real device, no real service, nobody has tried it by hand) belongs in Test and Manual, which stay partial until the hardware or service try.

## Experimental by decision (question for the owner)

The browser and mobile client family (F-CORE-14, F-CLIENT-01 to F-CLIENT-09) got the Notes sentence "Experimental by owner decision 2026-11-12 (browser and mobile clients; verified on the Chrome path only)". Their Impl, Test and Manual are unchanged and their Status stays `partial`.

The matrix has no status or column for "experimental by decision": `feature_matrix.rs` knows only done, partial, planned, blocked and deprecated, and the earlier experimental rows (for example F-VOICE-35, the wake phrase) are plain `partial` rows with the word in Notes. So only Notes were changed, and no status was invented.

Question: should the matrix gain a real representation, so that these ten rows (and F-VOICE-35, F-BOOT-31) stay partial on purpose and are counted separately from open work? Options: (a) a Notes marker the test recognises and the totals line counts as "experimental" instead of "impl open"/"unproven"; (b) leave as is. Until the owner answers, they count as ordinary partial rows and stay under the partial ceiling.
