# IYAKKI feature matrix

The single place to see what exists, what is half-done, what is next and what is on its way out.
It is written for people **and** for code assistants: one row per feature, a stable ID, the phase it belongs to,
how far along it is, and the unit tests that prove it. `crates/iyakki-core/tests/feature_matrix.rs` checks this file,
so a row cannot claim a test that does not exist or a status that contradicts its progress.

**Totals:** <!-- summary:start -->done 165 · partial 57 · planned 46 · blocked 2 · deprecated 1 · total 271<!-- summary:end -->

## How to use it

| You want to… | Do this |
|---|---|
| **Prioritise** | Take `planned` and `partial` rows, sort by `Pri` (P0 first), then by `Progress` (finish the nearly-done first). `blocked` rows say why in Notes. |
| **Start a feature** | Set Status `partial`, Progress above 0, and add the tests you write to the `Tests` column in the same change. |
| **Finish a feature** | Status `done`, Progress `100%`, and at least one test (or a `script:` check for things only a VM can prove). |
| **Deprecate** | Set Status `deprecated` and write what replaces it in Notes (`Replaced by F-…`). Leave the row in place until the code is removed; then delete the row in the same change. |
| **Add a feature** | New row with the next free number in its area. IDs never change and are never reused. |
| **Check your edit** | `cargo test -p iyakki-core --test feature_matrix` (also runs in `cargo test --workspace`). |

**Columns.** *ID* `F-<AREA>-<nn>`. *Phase*: P0 cross-cutting · P1 core + WASM · P2 snapshots and memory · P3 hardware and editor model · P4 packaging, network, swarm · P5 shell and permissions · P6 AI services (models, RAG, vault, MCP) · P7 assistant (chat sessions, skills, agent, voice) · P8 code editor · P9 persistence · P10 web and cloud. *Status*: `done` · `partial` · `planned` · `blocked` · `deprecated`. *Pri*: P0 critical … P3 nice to have. *Tests*: `crate::path::test_name` (the crate directory is `crates/<crate>`); `script:` entries are files that perform a check outside `cargo test` (QEMU boots, audits) and must exist.
